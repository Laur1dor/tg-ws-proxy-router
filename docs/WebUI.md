# Локальная веб-панель TGWS

Дополнение к существующей TUI: HTTPS, вход администратора, состояние службы,
SOCKS5/MTProto/FakeTLS, Worker, маршруты, ссылки подключения, журнал и
резервные копии настроек. Домен и дополнительные Python-зависимости не нужны.
Панель рассчитана на собственный Linux/systemd-хост и доступ из LAN.
Это не многопользовательская биллинг-панель: секрет каждого MTProto-входа
общий для его пользователей.

## Установка на существующий systemd-хост

Сначала сохраните каталог приложения и unit. Обновите исходники, сохранив
свой config.yml и .venv. Из каталога приложения под root:

```sh
./tgws.sh web init --bind 192.168.1.103 --port 8766
sed "s#__APP_DIR__#$(pwd)#g" deploy/tgws-web.service > /etc/systemd/system/tgws-web.service
systemctl daemon-reload
systemctl enable --now tgws-web.service
```

Подставьте собственный LAN-адрес. Команда init выдаст URL, логин admin и
случайный пароль. Сохраните пароль приватно. Повторный init не затирает
настройки. Без аргумента bind разрешён только loopback 127.0.0.1.
Публичные адреса и 0.0.0.0 запрещены. В интернет панель не пробрасывайте.

Сертификат создаётся локально, с SAN для выбранного IP. При первом входе
браузер попросит вручную подтвердить доверие к самоподписанному сертификату.
Проверяйте адрес; системные корневые сертификаты установщик не меняет.

```sh
tgws web info             # адрес панели
tgws web reset-password   # новый пароль; старые веб-сессии перестают работать
tgws                     # прежняя консольная TUI
journalctl -u tgws-web    # журнал службы панели
```

Если tgws отсутствует в PATH, используйте ./tgws.sh. Сброс пароля не требует
перезапуска прокси или веб-панели. Старый пароль восстановить из хэша нельзя.

## Работа и откат

Панель использует тот же config.yml. Пустые поля пароля SOCKS5 и секретов
MTProto сохраняют текущие значения. Неизвестные настройки и реквизиты выходов
сохраняются; выходы с паролями редактируются в TUI/конфиге. TUI также сохраняет
skip_front и дополнительные поля при записи. Ссылки с секретами показываются
только после входа и отдельного нажатия кнопки. Укажите внешний адрес для
удалённых пользователей или LAN-адрес для локальных.

При сохранении сравнивается версия конфига: устаревшую форму нужно обновить.
Если значения не изменились, файл не пишется и TGWS не перезапускается.
При изменениях создаётся приватная копия; файл заменяется атомарно с fsync.
Перезапускается только tgws.service. Если служба/порты не поднимаются,
возвращается предыдущий конфиг и выполняется попытка восстановления службы.
Последние 20 копий доступны для восстановления. Одновременное редактирование
в TUI, веб-панели и текстовом редакторе не рекомендуется.

Отключение веб-панели не останавливает прокси:

```sh
systemctl disable --now tgws-web.service
```

## Хранение и защита

webui-state/ содержит settings.json, хэш PBKDF2-SHA256 с солью, ключ/сертификат
HTTPS и backups/ с секретами прокси. Файлы создаются с правами 0600, каталоги
0700. В .gitignore исключены config.yml, webui-state/, venv и архивы.
Резервируйте состояние приватно; никогда не публикуйте его в GitHub.

Сессии находятся в памяти, действуют 30 минут, cookie Secure/HttpOnly/
SameSite=Strict. Есть проверка Host/Origin, CSRF, ограничение попыток входа,
размера JSON, числа соединений и времени ожидания. В обычном API секреты
скрыты, в журнале известные пароли/секреты маскируются. Данные не отправляются
сторонним сайтам, внешний JavaScript и шрифты не загружаются.

Панель запускается под root для редактирования существующего конфига и
управления systemd. Команды фиксированы: произвольного shell/терминала нет.
Доступ разрешается только с RFC1918/loopback-адресов и по настроенному Host.
Сервис отделён от самого прокси: остановка панели не прекращает Telegram.

Проверки: python -m unittest discover -s tests -p 'test_*.py'. Они проверяют
аутентификацию, CSRF, сброс сессии, скрытие секретов, сохранение дополнительных
полей, ошибку перезапуска с восстановлением и откат настройки. Все изменения
конфига в тестах выполняются во временных каталогах.
